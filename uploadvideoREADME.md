**Overview**
- **Purpose**: This document explains how to add a new video to the Rebecca Boombox player, what repository files to update, and notes about the service worker and deployment.

**Files & Locations**
- **Videos folder**: `public/videos/` — canonical location for all static video files used by the player.
- **Playlist**: `public/videos/index.json` — the playlist the app fetches (the app requests `./videos/index.json`).
- **Service Workers**: `service-worker.js` (root) and `public/service-worker.js` — control caching and update behavior for the PWA.
- **Build output**: `dist/` — generated by the build; do not edit directly.

**How To Add A New Video (step-by-step)**
- **Step 1: Add the file to the canonical folder**: copy or move the video file into `public/videos/`.
  - Example (PowerShell):

```powershell
# from repo root
Move-Item "videos\My New Song.mp4" "public\videos\My New Song.mp4"
# or copy
Copy-Item "C:\path\to\My New Song.mp4" "public\videos\My New Song.mp4"
```

- **Step 2: Update the playlist `index.json`**
  - Edit `public/videos/index.json` and add a new entry for your file. The playlist uses a simple array of entries. Keep the path relative to `public/`.
  - Example entry (insert into the array):

```json
{
  "title": "My New Song",
  "file": "My New Song.mp4",
  "path": "./videos/My New Song.mp4"
}
```

- **Step 3: Stage, commit and push**
  - Commands (PowerShell):

```powershell
git add "public/videos/My New Song.mp4" public/videos/index.json
git commit -m "Add: My New Song to public/videos and update playlist"
git push
```

- **Step 4: Optional build (if changing build assets or deploying from build)**
  - If you deploy from the Vite `dist/` build, run:

```powershell
npm run build
# then deploy the dist/ output as your hosting requires
```

**Service Worker (important for updates/clients)**
- We changed SW behavior in commit `bc0353a` (SW: network-first playlist + immediate activation (v3)). Key points:
  - The SW now calls `self.skipWaiting()` in `install` and `clients.claim()` in `activate`, which helps the new worker take control quickly.
  - The SW uses a **network-first** strategy for `videos/index.json` so new playlist updates are fetched from the network and then cached. This reduces the need for end users (e.g., your daughter's iPad) to clear caches or re-install the PWA to see new songs.
  - Other assets remain cache-first for offline reliability.

**How to make sure an iOS Home-Screen user gets the update**
- Have the user open the app URL once in Safari after you push the change. That visit allows the new SW to install and activate and then the home-screen PWA will pick it up.
- If the PWA is already installed and the user does not open Safari, updates sometimes delay on iOS. Opening the site explicitly in Safari is the minimal action.

**Quick testing locally**
- Run the dev server to test changes locally:

```powershell
npm install
npm run dev
# open http://localhost:5173 (or the port Vite shows)
```

- To test the service worker behavior you need to serve the built files over `http(s)` (Vite dev server works differently). Build and serve `dist/` with a static server, or deploy to GitHub Pages.

**Playlist formatting notes**
- Keep each entry consistent. Example minimal fields we use:
  - `title`: user-friendly title
  - `file`: filename in `public/videos/`
  - `path`: usually `./videos/<filename>` (used by the app when loading files)

**Troubleshooting**
- If a newly added video does not appear immediately on an iOS home-screen PWA:
  - Visit the app URL in Safari once to allow the new SW to install and activate.
  - If it still shows the old playlist, try opening Safari and doing a hard reload (pull to refresh) or clear Safari storage (last resort).
- If the video fails to play:
  - Ensure the file is a web-friendly format (MP4 H.264/AAC generally works across devices).
  - Check the console (dev tools) for CORS errors or 404 paths.
